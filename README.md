# Alliance Payments

## შესრულებული სამუშაო

- შეიქმნა Laravel 12-ის პროექტი.
- მომზადდა Laravel Breeze-ის ავტორიზაციისა და პროფილის საწყისი ფუნქციონალი React/Inertia-ით.
- დაინსტალირდა Laravel Sanctum.
- დაინსტალირდა Spatie Laravel Permission და `User` მოდელში დაემატა `HasRoles`.
- დაინსტალირდა Laravel Octane და მომზადდა მისი კონფიგურაცია.
- დაინსტალირდა Laravel Excel (`maatwebsite/excel` 3.1).
- დაინსტალირდა მიმდინარე Laravel-თან თავსებადი Brick Money 0.11.2 თანხების ზუსტი დამუშავებისთვის.
- დაინსტალირდა Pest 3.8.7 და მისი Laravel plugin 3.2.0; `composer.lock` განახლდა თავსებად PHPUnit 11.5.56-ზე.
- გასწორდა Vite 7-ისა და `@types/node`-ის თავსებადობა; შეიქმნა `package-lock.json` პაკეტების განმეორებადი დაყენებისთვის.
- წარმატებით სრულდება `npm run build`: TypeScript-ის შემოწმება და Vite-ის production build.
- აპლიკაციის დროის სარტყელად განისაზღვრა `Asia/Tbilisi`.
- შეიქმნა კლიენტების, პროექტების, ბინების, ხელშეკრულებების, გადახდის გრაფიკებისა და გადახდების მოდელები და მიგრაციები.
- შეიქმნა გადახდების განაწილების ისტორიის მოდელები და მიგრაციები: `AllocationRun`, `PaymentAllocation`.
- შეიქმნა Excel იმპორტის ფაილებისა და სტრიქონების აღრიცხვის მოდელები და მიგრაციები: `PaymentImport`, `PaymentImportRow`.
- ფინანსური მოდელების `price_minor` და `amount_minor` ველებს დაემატა `integer` cast-ები; თანხები ინახება თეთრებში.
- `App\Support\Money::toMinor()` GEL-ს Brick Money-ით გარდაქმნის მთელ თეთრებში; `9428.57` გარდაიქმნება `942857`-ად. Helper ამოწმებს დადებითობას და ბიბლიოთეკის შეცდომებს ქართული ტექსტით აბრუნებს.
- დაემატა `PaymentData`: ასუფთავებს სტრიქონებს მარტივი `foreach`-ით, ამოწმებს გადახდის ველებს და თანხას გარდაქმნის თეთრებში. ინარჩუნებს `"0"`-სა და პირადი ნომრის საწყის ნულებს; ვალიდაციის შეცდომები ქართულად ბრუნდება.
- დაემატა `RecordedPayment` DTO გადახდისა და ახალი ჩანაწერის შექმნის სტატუსის დასაბრუნებლად.
- შეიქმნა `AllocationStrategy` ინტერფეისი და `FifoAllocationStrategy` სერვისი. `sortBy()` გადახდებს ალაგებს `paid_at, id`-ით, შენატანებს — `due_date, id`-ით; განაწილება ითვლება მთელ თეთრებში, ერთი `while`-ით და ორი ინდექსით.
- დაემატა `RecordPayment`: პირადი ნომრით აკავშირებს გადახდას კლიენტთან, საბანკო ნომრით გამორიცხავს დუბლიკატებს და განსხვავებულ მონაცემებზე აბრუნებს ქართულ შეცდომას. დუბლიკატის შედარება იყენებს Eloquent-ის `isDirty()`-ს.
- დაემატა `ReallocateClientPayments`: ქმნის განაწილების ახალ ისტორიას, ჩანაწერებს ინახავს `createMany()`-ით და წარმატების შემდეგ ცვლის კლიენტის აქტიურ განაწილებას. ორივე Action იყენებს ტრანზაქციასა და კლიენტის ჩანაწერის ჩაკეტვას.
- `AppServiceProvider`-ში `AllocationStrategy` დაკავშირებულია `FifoAllocationStrategy`-თან.
- დაემატა ხელით გადანაწილების მარშრუტი `POST /clients/{client}/reallocate`, დაცული `auth`-ით და `payments.reallocate` უფლებით. `ReallocationController` იძახებს არსებულ Action-ს, აფიქსირებს მოქმედ მომხმარებელს და redirect-ით აბრუნებს ქართულ შეტყობინებას.
- დაემატა `GET /clients`, დაცული `clients.view` უფლებით: სახელით ან პირადი ნომრით ძიება, დალაგება, 20 ჩანაწერად დაყოფა და ხელშეკრულებების რაოდენობა. ფილტრებს ამოწმებს `ClientIndexRequest`, მონაცემებს ამზადებს `ListClients` Query.
- კლიენტების React/Inertia გვერდი მიბმულია დესკტოპისა და მობილურის ნავიგაციაზე; აჩვენებს ცარიელ შედეგს, ჩატვირთვას, ქართულ ვალიდაციასა და უფლებაზე დამოკიდებულ გადათვლის ღილაკს. Editor-ის გადათვლა იყენებს არსებულ მარშრუტს და აჩვენებს ქართულ flash შეტყობინებას; Viewer მხოლოდ სიას ხედავს.
- იმპორტისა და სტრიქონის სტატუსები წარმოდგენილია `ImportStatus` / `ImportRowStatus` enum-ებით. დაემატა `payment_imports.error_message` სვეტი, ახალი ფაილის საწყისი `queued` სტატუსი და მთვლელების `integer` cast-ები.
- მომზადდა `editor` და `viewer` როლები, 7 უფლება და დემო მომხმარებლების Seeder-ი; პაროლები იკითხება `.env`-იდან.
- ცალკეულ Seeder-ებში შეივსო 6 კლიენტი, 2 პროექტი, 12 ბინა, 7 ხელშეკრულება, 52 გრაფიკის შენატანი და 28 გადახდა.
- მონაცემების ექვსივე Seeder იყენებს `upsert`-ს: განმეორებით გაშვებისას მონაცემები ახლდება, ჩანაწერების ID-ები და კავშირები შენარჩუნებულია.
- Seeder-ებში პროექტები, ბინები და კლიენტები იძებნება უნიკალური ბიზნესგასაღებებით, ბაზაში წინასწარ განსაზღვრული ID-ების გარეშე.
- გადახდები Seeder-ში უკავშირდება კლიენტებს პირადი ნომრით; უცნობი გადამხდელის თანხა ინახება დაუკავშირებლად.
- `PaymentAllocationsSeeder` ავსებს FIFO განაწილებებს კლიენტის ყველა ხელშეკრულებაზე, ინახავს განაწილების ისტორიას და ზედმეტ თანხას ტოვებს გაუნაწილებლად. უცვლელი მონაცემებით განმეორებითი გაშვება ახალ განაწილებებს არ ქმნის.
- `DatabaseSeeder` ყველა Seeder-ს უშვებს საჭირო თანმიმდევრობით, საერთო ტრანზაქციაში.
- დამატებულია ბიზნესგასაღებების უნიკალური ინდექსები, მათ შორის პროექტის სახელსა და ქალაქზე და კლიენტის აქტიური განაწილების ID-ზე.
- შევსებულია კლიენტების, პროექტების, ბინების, ხელშეკრულებების, შენატანებისა და გადახდების Factories; გასწორებულია მოდელების import-ები.
- Factories ქმნის სხვადასხვა ქალაქის პროექტებს და ერთ პროექტში განსხვავებულ ფართობებს, სართულებს, ფასებსა და `free`/`sold` სტატუსებს. ბინის ფასი დამოკიდებულია პროექტის ქალაქსა და ფართობზე და ინახება მთელ თეთრებში.
- Factory-ით შექმნილი ხელშეკრულების ფასი ბინის ფასის 90–100%-ია; ხელშეკრულებასთან დაკავშირებული ბინა იღებს `sold` სტატუსს. თარიღები და გადახდების თანხები შემთხვევით გენერირდება.
- `InstallmentFactory::schedule()` ქმნის ყოველთვიურ გრაფიკს ხელშეკრულების ზუსტი ჯამით; `PaymentFactory` მხარს უჭერს დაკავშირებულ და დაუკავშირებელ გადახდებს, პირადი ნომრის ფორმატის შენარჩუნებით.
- Factories-ისა და Seeders-ის საკუთარი შეცდომის შეტყობინებები ქართულად არის დაწერილი.
- არსებობს ავტორიზაციისა და პროფილის საწყისი PHPUnit ტესტები.
- დამატებულია უნიკალური ინდექსების 7 PHPUnit ტესტი; ისინი წარმატებით გაეშვა Pest-ით.
- დაემატა Factories-ის 14 Pest ტესტი. მონაცემთა ბაზის ტესტების ჯგუფში წარმატებით დასრულდა 21 ტესტი და 230 შემოწმება.
- თანხის გარდაქმნა და არასწორი მონაცემების უარყოფა დაფარულია 16 Pest ტესტით.
- `PaymentData` დაფარულია 26 Pest ტესტით: ველების გაწმენდა, ვალიდაცია, ტიპები, თანხის სიზუსტე და არასაჭირო ველების გამორიცხვა.
- FIFO სერვისი დაფარულია 10 Pest ტესტით: რიგი, თანაბარი თარიღები, რამდენიმე ხელშეკრულება, ნაწილობრივი დაფარვა, ზედმეტი თანხა, ზუსტი თეთრები და განმეორებითი გამოძახება.
- გადახდის Action-ები დაფარულია 20 Pest ტესტით: ჩაწერა, დუბლიკატები, კონფლიქტები, უცნობი გადამხდელი, უკანა თარიღი, ისტორია და შეცდომისას ცვლილებების უკუქცევა.
- ხელით გადანაწილების HTTP ნაკადი დაფარულია 8 Pest ტესტით: სტუმარი, Viewer, პირდაპირ მინიჭებული უფლება, Editor, არარსებული/არასწორი კლიენტი, ისტორია და Inertia-ის ქართული flash შეტყობინება.
- კლიენტების სია დაფარულია 16 Pest ტესტით: წვდომა, ორივე როლი, ძიება, საწყისი ნულები, დალაგება, გვერდებად დაყოფა, ცარიელი შედეგი და ფილტრების ქართული შეცდომები.
- იმპორტის სტატუსები, საწყისი მნიშვნელობები, შეცდომის შენახვა და სტრიქონის მონაცემების სიზუსტე დაფარულია 10 Pest ტესტით.
- სრული Pest შემოწმება წარმატებით სრულდება: 152 ტესტი და 769 შემოწმება.
- დროებით SQLite ბაზაზე ბრაუზერით შემოწმებულია Editor/Viewer, ძიება, მეორე გვერდზე გადასვლა, გადათვლის ღილაკი და ქართული შედეგი; დესკტოპისა და მობილურის ხედი დათვალიერებულია.
- PostgreSQL-ზე დროებით ტრანზაქციაში შემოწმებულია გადახდის ჩაწერა, დუბლიკატი, ორი ხელშეკრულების FIFO და ისტორია; სატესტო ჩანაწერები rollback-ით გაუქმდა.
- Seeder-ები შემოწმებულია დროებით SQLite ბაზაში: თანხების სიზუსტე, კავშირები, განმეორებითი გაშვება, არსებული მონაცემების განახლება, FIFO, ზედმეტი თანხა და ტრანზაქციის უკუქცევა.
- განახლდა `.env.example` დემო მომხმარებლებისა და Octane-ის პარამეტრებით.
