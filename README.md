# Alliance Payments

## შესრულებული სამუშაო

- შეიქმნა Laravel 12-ის პროექტი.
- მომზადდა Laravel Breeze-ის ავტორიზაციისა და პროფილის საწყისი ფუნქციონალი React/Inertia-ით.
- დაინსტალირდა Laravel Sanctum.
- დაინსტალირდა Spatie Laravel Permission და `User` მოდელში დაემატა `HasRoles`.
- დაინსტალირდა Laravel Octane და მომზადდა მისი კონფიგურაცია.
- დაინსტალირდა Laravel Excel (`maatwebsite/excel` 3.1).
- დაინსტალირდა მიმდინარე Laravel-თან თავსებადი Brick Money 0.11.2 თანხების ზუსტი დამუშავებისთვის.
- დაინსტალირდა Pest 3.8.7 და მისი Laravel plugin 3.2.0; `composer.lock` განახლდა თავსებად PHPUnit 11.5.56-ზე.
- გასწორდა Vite 7-ისა და `@types/node`-ის თავსებადობა; შეიქმნა `package-lock.json` პაკეტების განმეორებადი დაყენებისთვის.
- წარმატებით სრულდება `npm run build`: TypeScript-ის შემოწმება და Vite-ის production build.
- აპლიკაციის დროის სარტყელად განისაზღვრა `Asia/Tbilisi`.
- შეიქმნა კლიენტების, პროექტების, ბინების, ხელშეკრულებების, გადახდის გრაფიკებისა და გადახდების მოდელები და მიგრაციები.
- შეიქმნა გადახდების განაწილების ისტორიის მოდელები და მიგრაციები: `AllocationRun`, `PaymentAllocation`.
- შეიქმნა Excel იმპორტის ფაილებისა და სტრიქონების აღრიცხვის მოდელები და მიგრაციები: `PaymentImport`, `PaymentImportRow`.
- ფინანსური მოდელების `price_minor` და `amount_minor` ველებს დაემატა `integer` cast-ები; თანხები ინახება თეთრებში.
- `App\Support\Money::toMinor()` GEL-ს Brick Money-ით გარდაქმნის მთელ თეთრებში; `9428.57` გარდაიქმნება `942857`-ად. Helper ამოწმებს დადებითობას და ბიბლიოთეკის შეცდომებს ქართული ტექსტით აბრუნებს.
- დაემატა `PaymentData`: ასუფთავებს სტრიქონებს მარტივი `foreach`-ით, ამოწმებს გადახდის ველებს და თანხას გარდაქმნის თეთრებში. ინარჩუნებს `"0"`-სა და პირადი ნომრის საწყის ნულებს; ვალიდაციის შეცდომები ქართულად ბრუნდება.
- დაემატა `RecordedPayment` DTO გადახდისა და ახალი ჩანაწერის შექმნის სტატუსის დასაბრუნებლად.
- შეიქმნა `AllocationStrategy` ინტერფეისი და `FifoAllocationStrategy` სერვისი. `sortBy()` გადახდებს ალაგებს `paid_at, id`-ით, შენატანებს — `due_date, id`-ით; განაწილება ითვლება მთელ თეთრებში, ერთი `while`-ით და ორი ინდექსით.
- დაემატა `RecordPayment`: პირადი ნომრით აკავშირებს გადახდას კლიენტთან, საბანკო ნომრით გამორიცხავს დუბლიკატებს და განსხვავებულ მონაცემებზე აბრუნებს ქართულ შეცდომას. დუბლიკატის შედარება იყენებს Eloquent-ის `isDirty()`-ს.
- დაემატა `ReallocateClientPayments`: ქმნის განაწილების ახალ ისტორიას, ჩანაწერებს ინახავს `createMany()`-ით და წარმატების შემდეგ ცვლის კლიენტის აქტიურ განაწილებას. ორივე Action იყენებს ტრანზაქციასა და კლიენტის ჩანაწერის ჩაკეტვას.
- `AppServiceProvider`-ში `AllocationStrategy` დაკავშირებულია `FifoAllocationStrategy`-თან.
- დაემატა ხელით გადანაწილების მარშრუტი `POST /clients/{client}/reallocate`, დაცული `auth`-ით და `payments.reallocate` უფლებით. `ReallocationController` იძახებს არსებულ Action-ს, აფიქსირებს მოქმედ მომხმარებელს და redirect-ით აბრუნებს ქართულ შეტყობინებას.
- დაემატა `GET /clients`, დაცული `clients.view` უფლებით: სახელით ან პირადი ნომრით ძიება, დალაგება, 20 ჩანაწერად დაყოფა და ხელშეკრულებების რაოდენობა. ფილტრებს ამოწმებს `ClientIndexRequest`, მონაცემებს ამზადებს `ListClients` Query.
- კლიენტების React/Inertia გვერდი მიბმულია დესკტოპისა და მობილურის ნავიგაციაზე; აჩვენებს ცარიელ შედეგს, ჩატვირთვას, ქართულ ვალიდაციასა და უფლებაზე დამოკიდებულ გადათვლის ღილაკს. Editor-ის გადათვლა იყენებს არსებულ მარშრუტს და აჩვენებს ქართულ flash შეტყობინებას; Viewer მხოლოდ სიას ხედავს.
- მომზადდა ბინების `WorkspaceQuery`: ნომრის, პროექტისა და ქალაქის ძიება, პროექტისა და სტატუსის ფილტრები, ფასით დალაგება და 20 ჩანაწერად დაყოფა. `WorkspaceRequest` ამოწმებს ფილტრებს ქართული შეტყობინებებით.
- `Money::formatMinor()` თეთრებს GEL-ის ზუსტ სტრიქონად გარდაქმნის, დიდი მთვლელების ფორმატირებისასაც float-ის გამოყენების გარეშე.
- ხელშეკრულებების Query მოიცავს კლიენტით/პროექტით ფილტრს, ძიებას, გრაფიკს, დაფარულ თანხასა და ნაშთს. ითვალისწინებს მხოლოდ აქტიურ `AllocationRun`-ს და არჩეულ თარიღამდე გადახდებს; ძველი ვერსიები აღარ აორმაგებს დაფარვას. შენატანის სტატუსებია `paid`, `overdue`, `partial`, `pending`.
- გადახდების Query მოიცავს ძიებას, კლიენტის ფილტრს, მიმდინარე განაწილებებს, ხელშეკრულებებზე ბმულებს, ზედმეტ თანხასა და დაუკავშირებელ გადამხდელებს. ანგარიშის თარიღი ბმულებში შენარჩუნებულია.
- ვადაგადაცილების Query დაფარვას `SUM`-ით აჯამებს, დაუფარავ თანხას ფილტრავს და მთლიან ჯამს ითვლის ბაზაშივე, პაგინაციამდე. გათვალისწინებულია კლიენტი, პროექტი, ძიება, მიმდინარე განაწილება და `as_of`; ამ დღის შენატანი ჯერ ვადაგადაცილებულად არ ითვლება.
- იმპორტისა და სტრიქონის სტატუსები წარმოდგენილია `ImportStatus` / `ImportRowStatus` enum-ებით. დაემატა `payment_imports.error_message` სვეტი, ახალი ფაილის საწყისი `queued` სტატუსი და მთვლელების `integer` cast-ები.
- `ReadPaymentRows` კითხულობს XLSX-ს private local დისკიდან: ამოწმებს ერთ ფურცელს, ექვსივე სათაურსა და 2000 სტრიქონის ზღვარს, გარდაქმნის Excel-ის თარიღებს და ინარჩუნებს რიგების პოზიციებსა და საიდენტიფიკაციო სტრიქონების საწყის ნულებს. ფორმულები არ გამოითვლება.
- `ProcessPaymentImport` ინახავს თითოეული სტრიქონის შედეგს (`imported`, `duplicate`, `rejected`), გადახდასა და FIFO განაწილებას ერთ ტრანზაქციაში. მთვლელები ყოველი სტრიქონის შემდეგ ახლდება; შეწყვეტილი დამუშავება გრძელდება უკვე შენახული სტრიქონების გამეორების გარეშე, ხოლო დასრულებული იმპორტი აღარ იცვლება.
- დაემატა `POST /imports`, დაცული `auth`, `payments.import` უფლებითა და წუთში 10 ატვირთვის ლიმიტით. იღებს მხოლოდ XLSX-ს, მაქსიმუმ 5 MiB; ატვირთვა ინახება private local დისკზე, იქმნება ფაილის ისტორია და პასუხად ბრუნდება redirect ქართული შეტყობინებით.
- `ProcessPaymentImportJob` იგზავნება ტრანზაქციის დასრულების შემდეგ, იყენებს გადაფარვისგან დაცვას და 60-წამიან timeout-ს. დასრულებული ფაილი იშლება, შეწყვეტილის ფაილი რჩება გაგრძელებისთვის; მომხმარებელს მიეწოდება ქართული შეცდომა, შენახული სტრიქონები და მთვლელები შენარჩუნებულია.
- დაემატა დაცული Inertia მარშრუტები: ბინები, ხელშეკრულებების სია/გრაფიკი, გადახდების სია/განაწილება, ვადაგადაცილება და იმპორტების სია/სტრიქონები. მთავარი გვერდი ხსნის ვადაგადაცილებას; საჯარო რეგისტრაცია დახურულია.
- `WorkspaceController` მონაცემებს იღებს Query-დან; საერთო React გვერდი აჩვენებს ქართულ სტატუსებს, ფილტრებს, ჯამებს, გვერდებად დაყოფას, ცარიელ/ჩატვირთვის/შეცდომის მდგომარეობებსა და დეტალების ბმულებს. კლიენტიდან ხელშეკრულებებზე გადასვლაც მუშაობს.
- იმპორტის ისტორია აჩვენებს ფაილისა და თითოეული რიგის შედეგს, მთვლელებსა და ქართულ შეცდომებს. მიმდინარე ფაილის სტატუსი ავტომატურად ახლდება; XLSX ატვირთვა მხოლოდ შესაბამისი უფლებით ჩანს, Viewer-ს შეუძლია ისტორიის ნახვა.
- დაემატა `GET /contracts/create` და `POST /contracts`, დაცული `contracts.create` უფლებით. ფორმა აჩვენებს კლიენტებსა და მხოლოდ თავისუფალ, ხელშეკრულების გარეშე ბინებს; მოწმდება თარიღები, დადებითი ზუსტი ფასი და 1–360 შენატანი.
- `CreateContract` ერთ ტრანზაქციაში კეტავს ჯერ კლიენტს, შემდეგ ბინას, ქმნის ხელშეკრულებასა და გრაფიკს, ცვლის სტატუსს `sold`-ზე და არსებული წინასწარი გადახდების FIFO-ს ხელახლა ითვლის. გაყიდულ ან უკვე დაკავშირებულ ბინაზე განმეორებითი შექმნა უარყოფილია; შეცდომისას მთელი ოპერაცია უკან ბრუნდება.
- `MonthlySchedule` თანხას მთელ თეთრებში ყოფს; ნაშთი ბოლო შენატანს ემატება. თარიღები ითვლება პირველი ვადიდან, თვის გადაცდენის გარეშე: 31 იანვარი → 28 თებერვალი → 31 მარტი. ხელშეკრულების ფასი შეთანხმებით შეიყვანება და ბინის კატალოგის ფასისგან შეიძლება განსხვავდებოდეს.
- დაემატა კლიენტების დამატება/რედაქტირება (`clients.create`, `clients.update`) React/Inertia ფორმებით. ინახება პირადი ნომრის საწყისი ნულები, მოწმდება უნიკალურობა; ხელშეკრულების ან გადახდის მქონე კლიენტის პირადი ნომერი უცვლელია, სახელი და ტელეფონი კი რედაქტირდება.
- `SaveClient` შესაბამის პირად ნომერზე ადრე დაუკავშირებელ გადახდებს აკავშირებს და FIFO-ს იმავე ტრანზაქციაში განაახლებს; თანხები და საბანკო ნომრები შენარჩუნებულია.
- დაემატა ბინების დამატება/რედაქტირება (`apartments.create`, `apartments.update`): პროექტი, უნიკალური ნომერი პროექტის ფარგლებში, სართული, ფართი და ზუსტი ფასი. ბინა იქმნება თავისუფალი; გაყიდული ან ხელშეკრულების მქონე ბინის შეცვლა Action-შიც იკრძალება. ერთდროული დუბლიკატის ბაზის შეცდომა ქართულ ვალიდაციად გარდაიქმნება.

- PostgreSQL-ის დროებით იზოლირებულ schema-ში ორი რეალური პროცესით შემოწმდა ერთ ბინაზე კონკურენტული გაყიდვა: ორივე ელოდება row lock-ს, იქმნება მხოლოდ ერთი ხელშეკრულება და ზუსტი გრაფიკი, მეორე მოთხოვნა იღებს ქართულ ვალიდაციას. შემოწმდა არსებული წინასწარი გადახდის განაწილება და დუბლიკატის rollback; schema შემოწმების ბოლოს წაიშალა.
- იზოლირებულ ბაზაზე ბრაუზერით შესრულდა ახალი კლიენტისა და ბინის შექმნა, ორივეს რედაქტირება, ახალი ხელშეკრულება და მისი 33.33 / 33.33 / 33.35 ₾ გრაფიკის ნახვა. შემოწმდა გაყიდული ბინის გამორთული ფორმა, ახალი ფორმის მობილური ხედი და Viewer-ისთვის დამატება/რედაქტირების ბმულების არჩვენება; React კონსოლში შეცდომები არ დაფიქსირდა.
- პროექტის დამატებას დაემატა 20 Pest ტესტი: სტუმარი, Viewer, პირდაპირი უფლება, ვალიდაცია, სახელისა და ქალაქის ერთობლივი უნიკალურობა, ბაზის კონფლიქტი, ბინის ფორმის წინასწარი არჩევანი და ახალი პროექტისთვის ბინის შენახვა. იზოლირებულ PostgreSQL schema-ში შემოწმდა შექმნა/დუბლიკატი/ბინის კავშირი; ბრაუზერში — პროექტის შექმნა და ავტომატური არჩევანი ბინის ფორმაში.
